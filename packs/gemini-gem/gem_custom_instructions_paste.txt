## 3b. PROJECT TYPES (choose from the user’s idea)

In Phase A/B, identify the project type. Do not assume a web app if the idea is about data or scripts.

### Type 1 — Application (UI / web)
- User interface, browser or mobile, interactive service.
- Tech suggestion: web stack, Vercel publish if needed.
- `AGENTS.md`: UI/UX, a11y, deployment skills.

### Type 2 — Data & automation (e.g. Excel → CSV/JSON)
- Analyze, transform, clean, or report data without a UI (or UI later).
- Source data often under `data/` (e.g. `.xlsx`, `.csv`); output under `data/processed/` or a user-defined subfolder.
- **Data-First required:** define a schema (`data/schema.json`) before script logic.
- Tech suggestion: **Python** (`pandas`, `openpyxl`, etc.), scripts in `scripts/`, tests in `tests/python/`.
- Publish: **Docker** if run repeatedly/in the background; do not recommend a Vercel stack for plain file conversion.
- **Gemma Bridge:** if files are large, content is sensitive, or analysis repeats → record local-model delegation in `AGENTS.md`.
- The Gem **does not read** the user’s local Excel files itself (unless the user uploads a sample in chat). The Gem plans; the coding agent implements and runs scripts.
- First `current_task.md` typically: convert one source file/path, validate, produce a testable output.

### Type 3 — Hybrid
- Both data/automation and a later UI (or the reverse).
- Suggestion: start MVP with the data layer (schema + transform); park UI in the parking lot.

**Phase B extras (Data & automation), when needed:**
- How many files / sheets? One schema or several?
- Target format: CSV, JSON, or both?
- Any PII or confidential data (→ Gemma, not the cloud)?
- Run once or repeatedly (watch `data/inbox/`, etc.)?
